# jax_rheology

Differentiable rheology in JAX: computational fluid dynamics (CFD) solvers for generalized-Newtonian and viscoelastic
flows, tensor-basis neural-network (TBNN) constitutive closures, and training utilities
for learning constitutive models from flow-field observations.

This is the code companion to A. Sunol et al., *Learning constitutive models and rheology from partial
flow measurements*, [arXiv:2510.24673](https://arxiv.org/abs/2510.24673). It includes `diff_rheo` (by
James Roggeveen), the differentiable bulk-rheometry fitting package used for the model-selection results.

## Installation

Two conda environments are used: one for the solvers and training
([`environment.yml`](environment.yml)), one for the rheometry fitting
([`environment_diff_rheo.yml`](environment_diff_rheo.yml), requires diffrax). They carry the exact pins
the paper results were produced with, including the CUDA build of jaxlib, which pip fetches from the JAX
release index named in the file. On a machine without a GPU, pip resolves the CPU build of jaxlib instead
and everything except the GPU-scale runs still works.

```bash
conda env create -f environment.yml
conda activate cfd_md_optimization
pip install -e .
```

The editable install is what makes `import jax_rheology` work from outside the repository; the vendored
`jax-cfd`, `jax_ib`, and `diff_rheo` trees are used in place rather than installed, and the package adds
them to `sys.path` on first use, so keep the checkout where it is.

## Quickstart

```python
from jax_rheology import Simulation, geometries, models

sim = Simulation(
    geometry=geometries.Constriction(nx=256, ny=128, pressure_gradient=5.0),
    model=models.carreau_yasuda(eta_inf=0.02, eta_0=1.0, lam=5.0, n=0.5, a=2.0),
    dt=1e-5, inner_steps=200, outer_steps=100,
)
trajectory = sim.run()
```

See [`examples/`](examples/) for forward simulation, TBNN training, and running a full experiment from a
config file. 

## Where output goes

Everything the code writes lands under `work/` unless you pass an explicit output directory, and the
verification suite writes to `verify_data/`; neither is tracked.

## Reproducing the paper

Each paper figure and table generated by this repository maps to one command in
[`REPRODUCE.md`](REPRODUCE.md). The underlying data is deposited at Zenodo (reserved DOI
10.5281/zenodo.22184699). A verification suite (`python verify/run.py --level quick`) checks regenerated
results against the published ones.

Figures 4a and 7, Supplementary Figures S16–S20, and the model-selection tables are produced by
`diff_rheo`; see [`diff_rheo/scripts/`](diff_rheo/scripts/) and
[`tbnn_model_selection/`](tbnn_model_selection/).

Two pipelines draw the figures. The [`paper_figs`](paper_figs/) package generates the viscoelastic and
elastoviscoplastic figures (Figs. 5–6 and Supplementary Figs. S7–S15): each panel is a no-argument
callable, all file access goes through `paper_figs.data_paths` and `paper_figs.loaders`, and
`experiments/figures.py` regenerates the whole set in one command. The instantaneous figures (Figs. 2–4,
S1–S6) are generated by the notebooks in [`notebooks/`](notebooks/), reading the deposited bundle.

## Tests

The verification suite in [`verify/`](verify/) is this project's test suite, and every check compares
regenerated numbers against the recorded values in `verify/expected.json`.

`python verify/run.py --level quick` needs nothing but a clone: it checks that the vendored packages
resolve, that the paper loss mask rebuilds to its recorded hash, that the duplicated closure definition
still matches the library, and that the three examples run. `--level full` adds the figure,
model-selection, and bundle comparisons, which need the deposited data, and the solver checks, which need
a GPU and run through two batch jobs. Anything whose data or hardware is absent skips with a line saying
what it wanted, so the suite is runnable anywhere; [`REPRODUCE.md`](REPRODUCE.md) lists the variables that
turn the skips into runs.
